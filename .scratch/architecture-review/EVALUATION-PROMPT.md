# You are the architecture evaluator

You are a principal engineer and LLM-systems designer. You have one job:
decide how first-principled should generate a followable Dependence Tree
from a typed word, using LLM calls plus code, then write the prompt that
tells the next agent how to map the rewrite.

The current repo was vibe-coded through many tickets. Stages, prompts,
gates, timeouts, models, and "never retry" rules have been patched around
each other. Earlier research already falsified the original three-stage
funnel. Later code tried to rescue it with schemas, shuffles,
deterministic layout, coercions, and one-shot repairs. The product still
does not reliably emit a Tree a curious adult can walk.

You are allowed to throw the current call graph away. Matching
`realityMap.js` is not a success criterion. Matching the mission and the
learner-facing Tree is.

Do not be polite about sunk cost. Do not propose another prompt retune of
the same three calls unless you can show, from evidence in this repo, why
the previous falsification no longer applies. Do not invent a fourth
"critic" LLM call as the first idea. Do not treat JSON validity as
followability.

## 1. Product (locked)

Mission, immutable, `docs/MISSION.md`:

> Reduce the cognitive distance between the learner's mental model and
> reality.

The learner types a word or phrase. The system must produce a Reality Map
and draw it as a Dependence Tree: supporting knowledge above, the typed
concept (crown) at the bottom, a walkable trunk, side fan-in, cards that
hold knowledge (label, layer caption, short gloss), arrows that carry the
warrant (`because`) rather than a hero-and-date card. History on hover
when known; UNKNOWN is legal and must not be invented.

**Dependence** is the drawn relation: A rests on B when A cannot exist or
be understood without B. Chronology (discovery order, invention lists,
"came before") is not the layout.

**Followability** is the product bar: one walkable spine for a curious
adult who opens rabbit holes. The mechanical JSON gate is not this bar.
Danny scores 0/1 on laptop, battery, photosynthesis, and recursion.

Gold words stay those four. They are the acceptance set.

Tutor chrome is parked. Learner Mental Model as a tab is parked. Nested
Trees from a node click are out. No accounts, no DB as a prerequisite for
the first working generator. No web grounding required for v1 (model
knowledge only).

## 2. Locked assumptions (questions that were not asked)

Treat these as true unless the repo clearly contradicts them. State any
override.

1. **Working means:** typing a gold word on the live app yields a
   non-empty learner-facing Tree that passes a mechanical structural
   check AND is followable (Danny could walk it). Empty maps,
   `invalid_model_output`, and timeline-shaped stacks are failure.
2. **Restructure is allowed.** Files, folders, stage names, schemas,
   number of LLM calls, who emits layout, even replacing the Netlify
   background-job shape, are all in scope if they are required to get
   working Trees. Do not preserve a bad pipeline because tickets locked
   it.
3. **Keep if cheap:** static `src/` frontend, Chapel display contracts
   (crown at bottom, cards, `because` on shafts, hover), client poll
   wait-state, OpenAI-compatible transport, no React rewrite unless you
   can show the current UI is the blocker (it is not).
4. **Provider reality:** prod is OpenRouter. Default model has moved
   (paid Nemotron, then `stealth/ox-alpha`, then `z-ai/glm-5.3-flash` in
   `src/lib/agent/llm.js`). Models disagree on JSON Schema, reasoning
   fields, and whether thinking and structured output can coexist. The
   architecture must not depend on one vendor quirk. Name the model
   capabilities you assume.
5. **Latency:** a minute-scale build is acceptable. Multi-hour builds
   are not. Host limits matter (Netlify background ~15 min; client poll
   14 min). Per-call abort in transport defaulted to 240s and was later
   raised to 600s in the generator. Do not "fix quality" by raising
   timeouts.
6. **Cost:** a few tens of cents per Tree is fine. Unbounded repair
   loops and giant hidden CoT dumps are not.
7. **Honesty:** UNKNOWN is first-class. Do not invent discoverers or
   dates. Do not coerce UNKNOWN records into looking exact.
8. **One background init** is a preference, not a religion. Client-chained
   stages were rejected because of UX and double-spend risk, not because
   three serial calls are metaphysically required.
9. **The next agent is a coding agent** with this repo. Your output is
   the spec it will follow. It will not re-derive philosophy. It will
   implement a map of tickets or a single rewrite plan, whichever you
   judge will actually ship working Trees.

## 3. What you must decide (the actual questions)

Answer these in order. Each answer needs a cause, not a slogan.

1. **What is the generator actually trying to compute?** Separate:
   inventory of ideas, warrants (why A rests on B), graph topology,
   layering/layout, learner-facing copy, honesty marks. Which of those
   must be LLM, which must be code, which must not exist?
2. **Why the current call structure fails**, with evidence from this
   repo (diagnostics, forensics, live captures, gate errors, transport
   quirks), not from generic LLM folklore.
3. **What the current code does that fights itself** (contract vs
   implementation). List the contradictions. They are load-bearing.
4. **The correct call graph** for best outputs: sequence of calls,
   inputs/outputs of each, schemas, what code does between calls, what
   is never asked of the model. Draw it as a pipeline. Include
   failure/repair policy that will not recreate the killed "rescue with
   prompt machinery" pattern.
5. **What to delete** (stages, fields, gates, parked engines, display
   constraints that leak into prompts).
6. **What to keep** (transport lessons, poll/job contract, Chapel
   renderer, mmg validator if still the right schema).
7. **Migration:** greenfield generator behind the same `/api/agent`
   init, or strangler, or full rewrite. Pick one and say why.
8. **Falsification test** for the new design, tighter than "JSON
   parsed". What would make you kill THIS proposal?

## 5. Current LLM call graph (as of this writing)

This is a snapshot so you can attack it. Verify against the files; if
code drifted, trust the code.

### Init (the product path)

Client: `generateTree` -> `POST /api/agent` with `{ phase: "init", word,
jobId }`. Netlify background function returns empty 202, writes snapshots
and a terminal record to Blobs. Client polls `GET /api/agent-status?job=`.

Server: `handleInit` -> `generateRealityMap` with injected `callLLM`
wrapping `callChatCompletion`.

**Three serial stages, same model, JSON mode:**

1. **Chronology** (no JSON Schema). System prompt: short ordered chain of
   target-specific capability regimes (`c1..cN`), physical ancestry
   default. User payload: `{ concept }`. Gate: `chronologyProblems`.
   Normalize enum case. On gate fail: **one repair call** feeding up to 8
   error strings plus the previous reply. Snapshot published if accepted.

2. **Epiphanies** (JSON Schema `buildEpiphaniesJsonSchema`, regime ids
   enum-locked). Joints between regimes with history
   `{ certainty, who, when, observation, uncertainty_note }`. DeepSeek
   path downgrades schema to `json_object`. Then `normalizeEpiphanies`:
   renumber ids to `e1..eN`, coerce joint_kind, derive/fix certainty,
   empty UNKNOWN facts, rewrite regime names to ids, empty
   `candidate_node` to null. Gate: `epiphaniesProblems`. **As shipped in
   `generateRealityMap`, Epiphanies has no repair loop** (Chronology and
   Arrange do). Snapshot published if accepted.

3. **Connect / Arrange.** Inventory of regimes + joints is
   **Fisher-Yates shuffled**. Model must emit `{ concept, edges: [{ from,
   to, because, evidence_ids }] }` under `buildArrangeJsonSchema` (ids
   enum-locked). Code `deterministicArrange`: nodes from inventory,
   cycle-break, synthesize crown id `target`, add crown edges, break
   undirected cycles, longest-path layers, trunk, provenance with
   `discarded_input_ids: []`. Then `arrangeCheck` (roles, observation
   basis on EPIPHANY nodes, acyclicity, connectedness, one crown,
   trunk, provenance accounting) then `listnessProblems` (flat list,
   unbranching path, stepwise stack). On fail: **one repair call** with
   errors and a "skip a layer / branch" hint.

Transport defaults inside `generateRealityMap`: `thinking` false unless
overridden; OpenRouter `reasoningEffort: "low"` always; `maxTokens`
65536; `timeoutMs` 600000. `llm.js`: on OpenRouter, `thinking: false`
omits `reasoning` unless effort is set (effort is set, so low reasoning
is sent). DeepSeek thinking disabled when `thinking === false`. JSON in
`reasoning_content` is copied into `content` if content is blank. 429
retried up to 4 times. Empty `choices` is a throw.

Learner payload: checked `map` only. Diagnostics (chronology, epiphanies,
provenance, prompts) stay server-side except learner-safe snapshots
during `running`.

## 6. Evidence you must confront (do not skip)

### Falsification (2026-08-20)

Original Stage 3 asked the model to emit the global map (nodes, layers,
trunk, provenance). On 3/4 gold words Arrange preserved Chronology as a
flat/list-like structure (`CHRONOLOGY_CAPTURE`). Photosynthesis died at
Epiphanies: every history `UNKNOWN` with non-empty facts (prompt dropped
the emptiness sentence; gate still required it). Learner maps empty. The
map's own rule: kill the funnel, do not retune, do not add a repair
loop. Replacement candidate: unordered inventory, evidence enrichment,
code arranges. Ticket 11 implemented a shuffle + edge-set + deterministic
layout. Live gold run + Danny walk were still pending in the ticket file.

### Forensics (11)

Chronology 4/4 shape-pass. Epiphanies 3/4. Arrange 0/3 when it ran:
model invented a new JSON shape every time because the prompt had no
schema and no example. Order preservation 1:1 with inputs. Gate errors
were schema/contract, not "the model is dumb."

### Provider

`:free` could not constrain JSON Schema. DeepSeek rejected
`json_schema`. Thinking-on Epiphanies dumped 34k chars of hidden thinking
and left non-JSON content. Council locked Option A (thinking off, schema
on Epiphanies). Later the default OpenRouter model **mandated** reasoning
(`effort: "none"` -> HTTP 400), so maps omit disable and now send
`effort: "low"` to stop 2-minute thinking per stage. Schema is a hint on
some models; `normalizeHistory` exists because stealth/ox-alpha omitted
required fields. `maxTokens` was raised to 65536 because thinking burned
the completion budget and truncated JSON.

### Design contradictions already in the tree

These are examples. Find more.

- Docs: "each stage once, no repair." Code: Chronology repair + Arrange
  repair. Ticket 11 live work still open.
- Docs: EPIPHANY is an arrow warrant, not a card. Arrange still turns
  every Stage 2 item into a graph **node** with `role: "EPIPHANY"`, then
  Chapel tries not to render those as cards. Dual ontology.
- Stage 1 is an **ordered** chain, then Stage 3 is told order is
  meaningless. Anchoring is predicted in `round-1-verdict.md` and then
  observed in captures.
- Stage 2 joints already contain `from_regimes` / `to_regimes` (an edge
  set). Stage 3 asks for another edge set over a shuffled mix of those
  joints **and** the regimes. The model is asked to reconnect things that
  already claim connections.
- Provenance accounting requires use-or-drop; deterministic arrange
  currently uses everything and discards nothing (`discarded_input_ids:
  []`). Drop permission was the anti-capture mechanism in the lock.
- `listnessProblems` is a heuristic pinned to old fixtures. It can reject
  a true chain-of-dependence (recursion may be nearly a path) or accept
  a messy DAG that is still a table of contents.
- Crown edges are synthesized in code ("target rests on every current
  top"). Topology is therefore partly a layout hack, not a model of
  Dependence.
- Normalization rewrites model beliefs (certainty, ids, names) so the
  gate passes. That hides generator failure and can launder UNKNOWN.
- `arrangeCheck` still wants history **on EPIPHANY nodes**. Display wants
  history on arrows. The schema is fighting the chrome.
- Spec section 7 still describes chat+map tutor product. Home is Tree-only.
- `.audit/architecture.md` says fix-not-rebuild because transport/job
  scars are expensive to relearn. That is true for Netlify/OpenRouter
  glue and false if the **task graph** is the defect.

### Prior art already summarized in-repo

`13-prior-art-patterns.md`: shipped systems extract parts (entities,
triples, pairwise prereqs) and arrange in code (Leiden, PPR, topo).
Nobody ships "LLM emits the finished global teaching tree in one JSON
object." Pairwise prerequisite classification is the education-research
standard. Collapse-to-list is explained by position bias, constraint
overload, and NULL-label bias (avoid UNKNOWN).

You may use this. You may also reject ticket 11's particular encoding of
it (shuffle + one edge-set call + longest-path layers) if that encoding
is still asking the model for a global graph.
